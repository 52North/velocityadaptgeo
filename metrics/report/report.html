The reasoning context never changed. Only the catalogue did.

Subtract the tool definitions from both runs and what is left — system prompt, conversation, graph state, model reasoning — is 35,245 tokens under MCP and 36,301 under pgvector. A 3% difference. All 95,109 tokens saved came from not shipping 21 process definitions the model was never going to use.

Context per call

Both runs made 13 calls through the same node sequence. They are indistinguishable until call 2 — the first moment tool definitions enter the prompt.

Read this with three caveats

One run per variant. The headline pair is a single 13-call pgvector turn against a single 13-call MCP turn. No variance, no error bars. The 61% context gap is far larger than plausible run-to-run noise; the 15% wall-time gap is not.

The MCP baseline is older. Those runs saw 26 tools where the registry now holds 25 — consistent with cool_spots still being indexed at the time. It appears in neither MCP graph, and both variants built the same 5 nodes, so the comparison holds. But roughly one process worth of definition tokens is counted against MCP that pgvector never had to carry.

runs.jsonl was trimmed mid-session. It held four records at the start of this session and three at the end; two earlier pgvector runs are gone. Re-running MCP against the current 25-process registry would close the first two gaps at once.
