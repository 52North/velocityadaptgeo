# prompt-review

Manual review of the paraphrases generated by [`prompt_gen`](../prompt_gen). It only reads and writes files in a run folder (see [FORMAT.md](FORMAT.md)), so it needs neither the models nor the generator's code.

## Usage

```
uv run prompt-review ../prompt_gen/out/<run_id>            # full-screen review
uv run prompt-review ../prompt_gen/out/<run_id> --summary  # per-category counts, then exit
```

Decisions are saved to `<run_dir>/reviewed.jsonl` after every change. `candidates.jsonl` is never changed.

## Files

`src/prompt_review/`:

- `cli.py`: the `prompt-review` command.
- `app.py`: the full-screen Textual app: list screen, review page, category and note dialogs.
- `state.py`: candidates, decisions, filters, sort and navigation, and the summary counts; no file access or drawing.
- `render.py`: the Rich renderables: review page, list rows and preview, summary table.
- `data.py`: reads the run folder and saves `reviewed.jsonl`.
- `similarity.py`: live closest matches from the generator's `embeddings.jsonl`.

`tests/`: pytest (`uv run pytest`).

## Live similarity

With the run's `embeddings.jsonl` (written by the generator; for older runs `prompt-gen backfill-embeddings <run_id>`), the closest matches are recomputed after every decision, against all other kept paraphrases: accepted in review, or accepted by the gates and not reviewed yet. The details show them under **Now**, and the matches stored at generation (earlier gate-accepted paraphrases only, what the gate's near-duplicate check saw) under **At generation**. A kept paraphrase whose closest kept paraphrase in its category is above the run's near-duplicate threshold is marked "kept near-duplicate of …", and the filter **kept near-duplicates** steps through them. `--summary` adds their count.

## Screens and keys

The reviewer starts on a **list** of all candidates in the current filter: one line each, with the run number, key, current category (`→` when moved), the gates' result, your decision, the similarity to the closest kept paraphrase in its category (red over the near-duplicate threshold), the semantic similarity to the seed (the generator's `sem` score) and the start of the prompt. The highlighted row's full text and closest match are shown below the table. Enter opens the **review page** for that candidate; Esc returns to the list at the same row. Both share the filter, sort order and position.

List:

| Key | Action |
|---|---|
| ↑ / ↓, PgUp / PgDn, Home / End | move |
| Enter | open the review page |
| a / r | accept / reject, then move on |
| u | undo the decision |
| f | cycle the filter |
| k | cycle the accepted/rejected filter: any, currently accepted, currently rejected |
| s | cycle the sort: file order, similarity (most similar first), category, seed similarity (most similar to the seed first) |
| q / Esc | quit |

Review page:

| Key | Action |
|---|---|
| ← / → | previous / next candidate (in the list's filter and sort order) |
| Home / End | first / last |
| a / r | accept / reject, then move on |
| c | accept into another category (number key, or ↑/↓ and Enter) |
| n | note on the current candidate (Enter saves, Esc cancels) |
| u | undo the decision |
| g | next unreviewed |
| d | details: closest matches, generator plan, discarded drafts, judge output |
| ↑ / ↓, PgUp / PgDn | scroll the page |
| f / k / s | cycle the filter / accepted/rejected filter / sort |
| Esc | back to the list |
| q | quit |

Filters: all, passed gates (the default), rejected by gates, unreviewed, kept near-duplicates (with embeddings), one per reject reason.

The accepted/rejected filter (`k`) applies on top of them: **any** (the default), **currently accepted** or **currently rejected**. Currently accepted means accepted in review (a move to another category counts), or not reviewed yet and accepted by the gates; the paraphrases that would be used if the review stopped now. For example "rejected by gates · currently accepted" lists the gate rejections overruled in review.
